# 模型配置与结论边界

## 当前状态

公开 Beta 的 `offline-demo` 使用已冻结响应回放，不调用任何模型。`development` 配置预留给在线 Adapter，但当前版本不会自动连接第三方服务。

模型凭证只能通过本地环境或专门的密钥服务提供，不能写入配置、Trace、报告、前端变量或 Git 历史。后端启动与健康检查不依赖 API Key。

## Candidate 模型为什么要有差异

跨模型对照的价值不是简单比较“谁更强”，而是观察 Skill 在不同基础能力、工具调用习惯和指令遵循特征下是否稳定。课程原型选择 GPT-5.4 与 GLM-5.2，意图是覆盖不同模型系列，减少只对单一模型优化的风险。

这仍只是实验设计理由，不是效果结论。要声称跨模型泛化，必须公开或留存：模型精确版本、请求参数、时间、重复次数、有效样本数、各难度分布和方差。

## Judge 模型为什么与 Candidate 分开

课程原型选择 GPT-5.5 作为 Judge，是基于更强代码语义理解和结构化输出能力的工程假设，并用于避免 Candidate 自评。真正证明它适合作为 Judge，还需要与盲化人评金标准比较。

建议至少记录：

- 总体一致率与 Cohen's kappa；
- PASS/FAIL/INCONCLUSIVE 混淆矩阵；
- 不同 L1/L2/L3 难度下的一致率；
- 同一输入重复判定的稳定性；
- 误判案例及修订后的回归结果。

如果没有这些数据，只能说“选用了该 Judge”，不能说“Judge 已被证明准确”。

## Adapter 约束

新的模型 Adapter 必须：

- 显式配置 provider 与 model，不使用隐藏默认值；
- 保存模型标识、参数和请求/响应哈希；
- 设置超时和重试上限，并区分服务错误与模型输出失败；
- 在保存前移除凭证与不必要的个人数据；
- 保持 D0、C_auto、C_forced 除 Skill 条件外完全一致。
