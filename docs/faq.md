# 常见问题

## 公开演示为什么只有一个 TestCase？

它的目标是完整展示链路，而不是形成排名。课程项目中的私有用例、GT、原始运行和第三方 Skill 存在保密或授权边界，不能直接公开。后续只接收来源清晰、经复核并可再分发的案例。

## TestCase 是固定还是自动生成？

系统支持两种来源，但进入正式评测前都必须人工复核并冻结。自动生成只是候选资产生产方式，不意味着自动获得有效性。

## 为什么失败不能直接扣 Skill 分？

因为同一失败表象可能来自 Runner、输入资产、Skill 未加载、证据缺失或模型输出。必须先定位第一个真实偏离点，详见[责任归因](bad-case-attribution.md)。

## Judge 会不会理解错或产生幻觉？

会。公开演示因此使用确定性规则 Judge。LLM Judge 必须受 Atomic Assertion、结构化 Schema 和 Evidence Bundle 约束，并通过人评一致性数据校准；证据不足时输出 Inconclusive。

## 为什么不公布真实模型分数？

目前没有随仓库发布可审计的完整原始记录、样本规模证明和 Judge 人评校准数据。为了不把演示结果包装成实验结论，本仓库明确不提供模型排行。

## 运行目录为什么不能覆盖？

覆盖会破坏审计链，使修复前后的结果无法比较。每次定向重跑应获得新的运行标识，并关联原 Bad Case。

## Windows 中文路径安装失败怎么办？

部分 Python 发行版会错误解码可编辑安装生成的路径文件。将仓库放到英文路径，或使用 `python -m pip install ".[dev]"` 普通安装，不要使用可编辑安装。

## 可以上传公司的代码和 Skill 吗？

本地运行仍需遵守组织政策。不要把包含密钥、客户数据、内部源码或无权分享内容的报告提交到 GitHub。当前服务没有身份认证，不应直接暴露到公网。
